# Qrypt quantum entropy quickstart (for AI agents)

This file is the canonical agent instructions. Humans paste a short prompt that links
here and to the quickstart page; read THIS file (or AGENTS.md in the repo) for the full
rules. A small tip at the top of the HTML pages is collapsed; the Quick/Isolated modes
section is always visible.

> Get an AES-256-GCM key from Qrypt quantum entropy. Plain HTTPS; no SDK exists for this API. Do not invent one.

## Expected short prompts (humans paste these)
- Quick Setup: `Set up the Qrypt quickstart and run the Python snippet. Follow https://qrypt-quickstart.pages.dev/ and https://qrypt-quickstart.pages.dev/llms.txt.`
- Isolated Setup: `Use Isolated Setup for the Qrypt quickstart in this folder (see QRYPT-ISOLATED.txt). Follow https://qrypt-quickstart.pages.dev/ and https://qrypt-quickstart.pages.dev/llms.txt.`

## Choose a mode
- **Quick Setup (default, no Docker):** follow the rules below. The human creates `.env`; you never read it. Behavioral safeguards only — not isolation.
- **Isolated Setup (Docker):** if `QRYPT-ISOLATED.txt` exists or the human said they are using `agent-sandbox/run.sh`, you have NO token. Implement the example, run mock tests, then tell the human to run `agent-sandbox/verify.sh --env <their-secret-path>` on the host. Do not ask for the token. Do not try to read any `.env`.

## FIRST: secrets
- NEVER ask the human to paste QRYPT_API_KEY into chat, a prompt, CLI args or source code.
- NEVER read, print, cat, head, sed, less, or dump `.env` or environment variables. NEVER enable verbose HTTP logging of Authorization headers.
- To check a `.env` exists without reading it: `test -f .env && echo set` (Quick Setup only). If that fails with Permission denied, you are misconfigured — stop and tell the human to use Isolated Setup.
- If you read .env or any credential by accident, stop and tell the human so they can rotate it.
- Keep the generated key in memory only. Do NOT write it to a file (no aes-256.key, no key.bin). "Generate a key" means: run the AES-GCM round trip and print the success line.
- At the end, remind the human: review this agent session for credential exposure and rotate any exposed or potentially compromised API credentials, including unrelated project credentials. Rotating the Qrypt token alone does not protect other secrets.

## Workflow (Quick Setup)
1. Read this file and the quickstart page.
2. Pick Python or Node (ask if unsure).
3. Implement using the official snippets below.
4. Install deps and run mocked tests (QRYPT_BASE_URL pointing at a mock, or `make check` in this repo).
5. Ask the human to create `.env` with QRYPT_API_KEY (token from https://portal.qrypt.com/trial-signup-entropy) and confirm it is set — without sharing the value.
6. Run the example. Report the success line only.

## Workflow (Isolated Setup)
1. Implement and mock-test as above. You will not have a real token; that is intentional.
2. Tell the human: `agent-sandbox/verify.sh --env ~/.config/qrypt/.env` (or their secret path).
3. Do not attempt workarounds for missing credentials.

## API
GET https://api-eus.qrypt.com/api/v1/quantum-entropy?size=1
Headers: Authorization: Bearer $QRYPT_API_KEY ; Accept: application/json
Response: {"random": ["<base64>"], "size": 1}. Each string decodes (standard base64) to 1024 bytes.
size counts KiB (1..512), NOT bytes. For one AES-256 key use size=1 and take the first 32 decoded bytes.

## Rules
- Python: use `requests` or set a custom User-Agent. Cloudflare blocks Python-urllib with 403 Error 1010.
- 400 bad size; 401 missing/malformed Authorization header; 403 wrong token OR quota reached (bad tokens return 403, not 401);
  429 rate limited (docs: 30 req/10 s, but live can return 429 about 1 s after a single prior call; no Retry-After): wait 10 s or more and never loop; 500/503 try again shortly. Exit non-zero on error.
