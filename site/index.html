llms.txt

Make an AES-256 key from quantum entropy

For AI coding agents

Prefer llms.txt (also linked in the page head) or the repo AGENTS.md. Never read, print or dump .env or environment variables, and never ask the human to paste the token into chat. Ask them to create .env themselves and confirm it is set. If QRYPT-ISOLATED.txt exists you have no token on purpose: run mock tests and ask the human to run agent-sandbox/verify.sh on the host. Human-readable modes: below.

Time target: about 5 minutes No SDK needed: one HTTPS GET, then standard crypto.

1. Get a token

Create an account at portal.qrypt.com/trial-signup-entropy and generate a token for the Entropy service. It is shown only once and is billed like a password: keep it secret.

2. Save it in .env

QRYPT_API_KEY=paste-your-token-here

Put .env next to the script and add it to .gitignore. Never print it, not even partly (no cat .env). To check the file exists, run test -f .env && echo set.

3. Run the snippet

Python 3.9+. Uses requests: Cloudflare blocks Python's built-in urllib User-Agent.

python3 -m venv .venv && .venv/bin/pip install requests cryptography python-dotenv
# Qrypt quickstart (Python): 1 KiB of quantum entropy -> AES-256-GCM key.
# Setup: pip install requests cryptography python-dotenv
# Then put QRYPT_API_KEY=<your token> in a .env file next to this script.
import base64
import os
import sys

import requests
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
from dotenv import load_dotenv

API = os.getenv("QRYPT_BASE_URL", "https://api-eus.qrypt.com")  # mock override

# One friendly message per failure. We never retry automatically.
HELP = {400: "400: size must be 1-512. It counts KiB, not bytes.",
        None: "QRYPT_API_KEY is missing: add to .env. Token: portal.qrypt.com/trial-signup-entropy",
        401: "401: Authorization header missing, malformed or expired.",
        403: "403: Token invalid OR monthly quota used. Check the token first.",
        429: "429: rate limited. Live can return 429 about 1 s after a single "
             "prior call; wait 10 s or more and never loop."}
# 500, 503 and anything else: Qrypt is busy or erroring, so try again later.

# Step 1: read the token from .env. Never print or log it.
load_dotenv()
token = os.getenv("QRYPT_API_KEY") or sys.exit(HELP[None])

# Step 2: fetch 1 KiB of entropy. A custom User-Agent avoids Cloudflare's
# block on Python's urllib; X-Qrypt-Client tags quickstart traffic.
headers = {
    "Authorization": f"Bearer {token}", "Accept": "application/json",
    "User-Agent": "qrypt-quickstart/1.0", "X-Qrypt-Client": "quickstart-py/1.0"}
try:
    resp = requests.get(f"{API}/api/v1/quantum-entropy", params={"size": 1},
                        headers=headers, timeout=15)
    if resp.status_code != 200:
        sys.exit(HELP.get(resp.status_code, f"{resp.status_code}: Qrypt is "
                          "busy or erroring. Try again shortly."))
    entropy_b64 = resp.json()["random"][0]
except (requests.RequestException, ValueError):
    sys.exit("Network error or non-JSON reply: check proxy/TLS, retry soon.")

# Step 3: decode first, then keep 32 bytes as the AES-256 key.
key = base64.b64decode(entropy_b64)[:32]

# Step 4: encrypt and decrypt a sample message with AES-256-GCM.
aes, nonce, message = AESGCM(key), os.urandom(12), b"hello, quantum entropy"
assert aes.decrypt(nonce, aes.encrypt(nonce, message, None), None) == message
print("Success: AES-256-GCM round trip with a Qrypt key (not shown).")

.venv/bin/python quickstart.py

Node 20.12+ (built-in fetch and process.loadEnvFile). No dependencies.

// Qrypt quickstart (Node 20.12+): 1 KiB of quantum entropy -> AES-256-GCM key.
// No dependencies. Put QRYPT_API_KEY=<your token> in a .env file here.
import assert from "node:assert";
import { existsSync } from "node:fs";
import { createCipheriv, createDecipheriv, randomBytes } from "node:crypto";

const API = process.env.QRYPT_BASE_URL ?? "https://api-eus.qrypt.com"; // mock

// One friendly message per failure. We never retry automatically.
const HELP = { 400: "400: size must be 1-512. It counts KiB, not bytes.",
  missing: "QRYPT_API_KEY is missing: add to .env. Token: portal.qrypt.com/trial-signup-entropy",
  network: "Network error or non-JSON reply: check proxy/TLS, retry soon.",
  401: "401: Authorization header missing, malformed or expired.",
  403: "403: Token invalid OR monthly quota used. Check the token first.",
  429: "429: rate limited. Live can return 429 about 1 s after a single " +
    "prior call; wait 10 s or more and never loop." };
// 500, 503 and anything else: Qrypt is busy or erroring, so try again later.
const fail = (msg) => { console.error(msg); process.exit(1); };

// Step 1: read the token from .env. Never print or log it.
if (existsSync(".env")) process.loadEnvFile(".env");
const token = process.env.QRYPT_API_KEY || fail(HELP.missing);

// Step 2: fetch 1 KiB of entropy (size counts KiB, not bytes).
const headers = { Authorization: `Bearer ${token}`, Accept: "application/json",
  "User-Agent": "qrypt-quickstart/1.0", "X-Qrypt-Client": "quickstart-js/1.0" };
const url = `${API}/api/v1/quantum-entropy?size=1`;
const res = await fetch(url, { headers }).catch(() => fail(HELP.network));
if (res.status !== 200) fail(HELP[res.status] ??
  `${res.status}: Qrypt is busy or erroring. Try again shortly.`);
const body = await res.json().catch(() => fail(HELP.network));

// Step 3: decode first, then keep 32 bytes as the AES-256 key.
const key = Buffer.from(body.random[0], "base64").subarray(0, 32);

// Step 4: encrypt and decrypt a sample message with AES-256-GCM.
const GCM = "aes-256-gcm", iv = randomBytes(12), message = "hello, quantum";
const enc = createCipheriv(GCM, key, iv);
const sealed = Buffer.concat([enc.update(message, "utf8"), enc.final()]);
const dec = createDecipheriv(GCM, key, iv).setAuthTag(enc.getAuthTag());
assert.equal(dec.update(sealed, null, "utf8") + dec.final("utf8"), message);
console.log("Success: AES-256-GCM round trip with a Qrypt key (not shown).");

node quickstart.mjs

What the API returns

One base64 string per KiB requested. Decode it before use; it never contains the key itself.

{
  "random": ["<base64 string: 1,024 random bytes when decoded>"],
  "size": 1
}

4. Expected output

Success: AES-256-GCM round trip with a Qrypt key (not shown).

Things that trip people up

  • size counts KiB, not bytes. Ask for size=1 (1,024 bytes) and take 32 bytes.
  • Base64-decode the string first; never use the text itself as the key.
  • Live can return 429 about 1 s after a single prior call; wait 10 s or more and never loop.
  • A wrong token returns 403, the same as an exhausted quota. Check the token first.
  • Never print, log or commit the key or token. Use fresh entropy for each key.

For AI coding agents — Quick Setup and Isolated Setup

Machine-readable rules: llms.txt. Repo: AGENTS.md. Paste a short prompt below; the agent should get everything else from those docs.

Two modes. Quick Setup is the default (no Docker). Isolated Setup is optional when you want stronger credential boundaries.

Option A — Quick Setup (default, no Docker)

Security warning. AI coding agents may access files containing credentials, including existing .env files, before reading these instructions. Credential values could appear in agent session logs. For this quick setup, use disposable API credentials where possible and rotate any credentials that were exposed or may have been compromised. For stronger protection, choose Isolated Setup.

  1. Paste this prompt into Claude Code, Codex, Cursor or another coding agent: 
    Set up the Qrypt quickstart and run the Python snippet.
Follow https://qrypt-quickstart.pages.dev/ and https://qrypt-quickstart.pages.dev/llms.txt.
  2. The agent reads the quickstart, picks a language, implements with the official snippets and runs the mock tests.
  3. When asked, create .env yourself (never paste the token into the chat): 
    QRYPT_API_KEY=paste-your-token-here
    Tell the agent only that it is set. Do not share the value.
  4. The agent runs the example (1 KiB → 32-byte AES-256 key → AES-GCM round trip) and reports the success line without displaying secrets.

End-of-workflow reminder: Review your agent session for potential credential exposure. Rotate any exposed or potentially compromised API credentials, including unrelated project credentials. Rotating the Qrypt token alone does not protect other secrets.

These rules are defense-in-depth, not enforceable isolation. Rotation does not make an earlier exposure harmless, and nothing here claims a no-logging guarantee. Prefer Isolated Setup when that matters.

Option B — Isolated Setup (Docker; agent never sees the token)

The agent runs in a container with no .env, no host home, no SSH keys, no cloud credentials and no Docker socket. Live verification is a separate host-side step that runs fixed snippets from this repo — never agent-modifiable code — with the real token.

Sample agent prompt (after the sandbox is running against a clean project):

Use Isolated Setup for the Qrypt quickstart in this folder (see QRYPT-ISOLATED.txt).
Follow https://qrypt-quickstart.pages.dev/ and https://qrypt-quickstart.pages.dev/llms.txt.
  1. Download the sandbox into one folder: Dockerfile, run.sh, verify.sh, test-isolation.sh, README.md. Then chmod +x agent-sandbox/*.sh.
  2. Keep the token outside the project the agent will see: 
    mkdir -p ~/.config/qrypt
# put QRYPT_API_KEY=... in ~/.config/qrypt/.env, then:
chmod 600 ~/.config/qrypt/.env
  3. Start the agent against a clean project directory (must not contain .env — run.sh refuses otherwise): 
    agent-sandbox/run.sh ~/qrypt-demo your-agent-command
  4. Inside the container the agent implements the example and runs mock tests. It has no token.
  5. On the host, after the agent finishes, run trusted verification: 
    agent-sandbox/verify.sh --env ~/.config/qrypt/.env
# -> verify python: PASS (AES-GCM round trip; key not shown)

Honesty about isolation: this blocks the common failure mode (agents reading .env). It does not claim Docker guarantees zero leakage. A malicious SANDBOX_DOCKER_ARGS that remounts your home directory, a compromised agent binary, or a container escape is out of scope. The boundaries we do claim are checked by agent-sandbox/test-isolation.sh.
