Troubleshooting

HTTP status codes

Symptom, likely cause and fix for each response
CodeSymptomLikely causeFix
400"'size' must be an integer between 1 and 512"size is 0, over 512, or not a number; often someone passed bytes (e.g. 32) thinking it was bytes.Use size=1; it returns 1,024 bytes. Slice 32 bytes for AES-256.
401"Missing or malformed Authorization header"No Authorization header, or it is not Bearer <token>. An empty .env value also causes this.Send Authorization: Bearer YOUR_TOKEN. Check .env is in the folder you run from. Note: expired tokens are documented to return 401.
403"Forbidden or entropy quota reached"Either the token is wrong (live API returns 403, not 401, for a bad token) or the monthly quota is used up. An HTML "Error 1010" page instead means Cloudflare blocked your client's User-Agent.Check the token first: no spaces or quotes, correct service (Entropy). Then check quota in the portal. For Error 1010, use requests or set a custom User-Agent; don't use Python's urllib defaults.
429Too many requestsMore than 30 requests in 10 seconds. The API sends no Retry-After header.Wait 10 seconds, then retry once. Never retry in a tight loop; request larger size instead of many calls.
500Internal errorProblem on Qrypt's side.Try again shortly. If it persists, contact support@qrypt.com.
503Entropy temporarily insufficientQrypt's entropy supply is briefly low.Try again shortly, with a delay. Don't loop.

Common mistakes

  • Using the base64 string as the key instead of decoding it.
  • Treating size as bytes.
  • Reusing the same entropy bytes for two keys.
  • Printing the key or token while debugging, or committing .env.
  • Leaving out Accept: application/json (the docs require it).
  • Assuming an SDK package exists; the API is plain HTTPS.
